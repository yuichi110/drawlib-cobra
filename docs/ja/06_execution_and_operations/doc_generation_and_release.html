ドキュメント自動生成（MD/Man/YAML）と配布

cobra.Command のコマンドツリーには、すべてのサブコマンド階層・概要（Short/Long）・使用例（Example）・フラグの型やデフォルト値が構造化データとして定義されています。そのため、Go のコマンド定義そのものを Single Source of Truth（単一の情報源） として扱い、Web ドキュメントサイトや UNIX の man ページを完全自動生成できます。Cobra 標準の github.com/spf13/cobra/doc サブパッケージと GoReleaser を組み合わせた本番配布パイプラインを解説します。

1. cobra/doc の4大ドキュメントジェネレータ

github.com/spf13/cobra/doc パッケージは、cobra.Command ツリーを再帰的に走査し（Hidden: true や Deprecated なコマンドは自動除外）、各サブコマンドごとに1つのリファレンスファイルを出力します。

出力フォーマット 単一コマンド出力（io.Writer） ツリー一括出力（ディレクトリ指定） フロントマター・リンク変換付き出力
Markdown（.md） doc.GenMarkdown(cmd, w) doc.GenMarkdownTree(cmd, dir) doc.GenMarkdownTreeCustom(cmd, dir, prepender, linkHandler)
Man ページ（.1） doc.GenMan(cmd, hdr, w) doc.GenManTree(cmd, hdr, dir) doc.GenManTreeFromOpts(cmd, GenManTreeOptions{...})
YAML（.yaml） doc.GenYaml(cmd, w) doc.GenYamlTree(cmd, dir) doc.GenYamlTreeCustom(cmd, dir, prepender, linkHandler)
ReST（.rst） doc.GenReST(cmd, w) doc.GenReSTTree(cmd, dir) doc.GenReSTTreeCustom(cmd, dir, prepender, linkHandler)

DisableAutoGenTag: true で Git の不要な差分（日付ノイズ）を防ぐ

デフォルト（DisableAutoGenTag: false）では、生成されたすべてのファイルの末尾に実行当日の日付タグが出力されます。

###### Auto generated by spf13/cobra on 10-Nov-2026

このままでは、コマンド仕様を1行も変更していなくても日次 CI のたびに全ドキュメントファイルに Git 差分が発生してしまいます。必ずルートコマンドに rootCmd.DisableAutoGenTag = true を設定してください。

  • cobra/doc はツリー走査時に親コマンドの DisableAutoGenTag: true をすべての子孫コマンドへ自動伝播します（doc/md_docs.go:91-95）。
  • さらに GenManTree では、Reproducible Builds（再現可能ビルド）標準の環境変数 SOURCE_DATE_EPOCH も自動的に認識されます（doc/man_docs.go:127）。

完全なドキュメント生成ツール実装例（cmd/gendocs/main.go）

package main

import (
	"fmt"
	"log"
	"os"
	"path/filepath"
	"strings"
	"time"

	"github.com/spf13/cobra/doc"
	"example.com/mycli/internal/cli"
)

func main() {
	rootCmd := cli.NewRootCommand()
	// 日付フッタを無効化し、Git 差分を 100% 決定論的（Deterministic）にする
	rootCmd.DisableAutoGenTag = true

	// 1. 静的サイト向けに YAML フロントマター付きで Markdown ツリーを生成
	mdDir := "./dist/docs/markdown"
	_ = os.MkdirAll(mdDir, 0o755)
	filePrepender := func(filename string) string {
		name := filepath.Base(filename)
		base := strings.TrimSuffix(name, filepath.Ext(name))
		title := strings.ReplaceAll(base, "_", " ")
		return fmt.Sprintf("---\ntitle: %q\nslug: %q\n---\n\n", title, base)
	}
	linkHandler := func(name string) string {
		return strings.ToLower(name)
	}
	if err := doc.GenMarkdownTreeCustom(rootCmd, mdDir, filePrepender, linkHandler); err != nil {
		log.Fatalf("markdown generation failed: %v", err)
	}

	// 2. UNIX セクション 1 の Man ページを生成
	manDir := "./dist/docs/man1"
	_ = os.MkdirAll(manDir, 0o755)
	fixedDate := time.Date(2026, 1, 1, 0, 0, 0, 0, time.UTC)
	header := &doc.GenManHeader{
		Title:   "MYCLI",
		Section: "1",
		Date:    &fixedDate,
		Source:  "MyCLI Enterprise",
		Manual:  "MyCLI User Manuals",
	}
	if err := doc.GenManTree(rootCmd, header, manDir); err != nil {
		log.Fatalf("manpage generation failed: %v", err)
	}

	// 3. YAML スキーマカタログを生成
	yamlDir := "./dist/docs/yaml"
	_ = os.MkdirAll(yamlDir, 0o755)
	if err := doc.GenYamlTree(rootCmd, yamlDir); err != nil {
		log.Fatalf("yaml generation failed: %v", err)
	}
}

2. Go リンカのデッドコード除去（DCE）とバイナリサイズの最適化

CI コンテナや開発者端末に配布される本番 CLI バイナリでは、ファイルサイズと起動速度が重要になります。Go のリンカ（cmd/link）のデッドコード除去（Dead-Code Elimination: DCE）と cobra/doc の関係を理解し、本番バイナリを最小限に保ちましょう。

本番バイナリを軽量に保つ3つの鉄則

  1. cobra/doc は cmd/gendocs/main.go に分離する:
    • github.com/spf13/cobra/doc は内部で go-md2man/v2、blackfriday/v2、yaml.v3 をインポートします。本番の cmd/mycli バイナリからこれらを切り離し、ビルド時専用の cmd/gendocs/main.go から NewRootCommand() を呼び出す構成にすれば、配布バイナリに Markdown パーサーや YAML ライブラリが含まれません。
  2. text/template と reflect.Value.MethodByName が DCE に与える影響:
    • Go のリンカ（cmd/link）は到達不能な関数やメソッドをバイナリから除去しますが、プログラム内で reflect.Value.MethodByName（text/template や html/template が内部で使用）が呼ばれると、どの構造体のメソッドが文字列名で動的呼び出しされるか静的に特定できないため、到達可能なすべての構造体のエクスポート済みメソッドがバイナリに残ってしまいます。
    • 独自のテンプレート処理を追加する際は、巨大 SDK クライアントを同じパッケージに抱え込まないよう分離するか、fmt.Fprintf ベースの出力関数（SetHelpFunc）を活用してください。
  3. リリースビルドでのシンボル・DWARF 除去:
    • CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" を指定することで、シンボルテーブル（-s）と DWARF デバッグ情報（-w）を除去し、バイナリサイズを大幅に削減できます。

3. GoReleaser による補完スクリプトと Man ページの同梱配布

brew install mycli や apt install mycli を実行した直後から <Tab> 補完と man mycli が使えるようにするには、cmd/gendocs/main.go で4種類のシェル補完スクリプトも同時出力し、.goreleaser.yaml でパッケージに同梱します。

// cmd/gendocs/main.go 内で4シェルの補完スクリプトを自動生成:
_ = rootCmd.GenBashCompletionV2(bashFile, true)
_ = rootCmd.GenZshCompletion(zshFile)
_ = rootCmd.GenFishCompletion(fishFile, true)
_ = rootCmd.GenPowerShellCompletionWithDesc(pwshFile)

生成した成果物を .goreleaser.yaml でアーカイブおよび Homebrew Formula にマッピングします。

version: 2
before:
  hooks:
    - go run ./cmd/gendocs
    - sh -c "gzip -9 -f ./dist/docs/man1/*.1"

builds:
  - id: mycli
    main: ./cmd/mycli
    env:
      - CGO_ENABLED=0
    flags:
      - -trimpath
    ldflags:
      - -s -w -X example.com/mycli/internal/cli.version={{.Version}}

archives:
  - id: default
    files:
      - LICENSE*
      - README*
      - dist/docs/man1/*.1.gz
      - dist/completions/*

brews:
  - name: mycli
    install: |
      bin.install "mycli"
      man1.install Dir["dist/docs/man1/*.1.gz"]
      bash_completion.install "dist/completions/mycli.bash" => "mycli"
      zsh_completion.install "dist/completions/mycli.zsh" => "_mycli"
      fish_completion.install "dist/completions/mycli.fish"
